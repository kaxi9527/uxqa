# QA大师 使用说明

## 用状态看板安排项目工作

在项目中打开「工作流」，默认显示六列「未测试、测试中、未修复、修复中、未复查、已完成」。可手动新建任务、从「验收任务」导入文档要求，或从问题详情点击「加入任务看板」。不同轮次的同一检查发现可以关联到同一张卡。点击「流程编排」可继续使用原有的逐步或自动模式。

拖卡到下游列，或点开卡片使用对应操作。初测通过可直接完成。修复中要记录改动和证据再提交复查。复查必须以原条件为依据，失败回到原卡的「未修复」。缺条件时选择「记录阻塞」，补齐后在原列继续。卡片详情可查看流转记录、原场景与修复对话。

「项目排期」决定新任务默认由系统安排还是等待人工分级。在卡片详情展开「优先级」可手动设定 P0–P3，或恢复系统安排。系统给出建议和理由；人工选择在复查失败后仍保留。「处理下一项」从当前可处理的任务中先选高优先级，同一 P 先复查，再继续已开始的工作。已完成、缺证据或待分级的任务保留在原列。该排序不改变流程编排中指定的步骤顺序。

### 运行文档验收任务

在项目「检查」中拖入正文文档。导入结果按原文位置列出角色、条件、操作和预期。点「生成验收任务」核对候选项，补全待确认字段，保存需要重跑的任务。可明确选择把本页摘录发给已配置的模型辅助识别。创建后的任务保留来源版本和原文。

在「工作流 → 验收任务」中编排并审阅场景。核对测试地址、角色、准备动作和每个断言；会写入测试数据的场景应使用可重复准备的测试环境。配置传播任务可绑定变更前、激活后、未改对象三个独立观测阶段。确认后，任务可以作为一列反复加入工作流。选择「运行任务」执行已保存的定义。

失败任务会出现在对应轮次的「问题处理」和工作台中。「让 AI 修复并复检」将条款与运行证据交给此项目的 Agent，记录实际修改的文件，并在相同测试地址重跑原场景及其对照。选择同轮设计区域时，可用的设计图、实测截图及区域坐标也会发给所选模型。展开修后复检可同时查看修前、修后的分阶段观测与未覆盖条件。

### 视觉区域、人工反馈与磁盘

在「视觉还原」中对齐同状态、同尺寸的设计稿和实测画面，展开「选择组件区域」。在已导入的设计图上点选组件、拖出矩形或用键盘填写像素坐标。页面有可识别的组件标记或开发态组件来源时，QA大师 记录对应组件，并列出本轮实际观察到的使用页面；缺少映射时可人工指定。为每种状态和视口分别取证。在「组件、状态与断点」查看已有比较。

在问题详情里标记确实有问题、可以接受或漏检。工作流也能记录整轮漏检和参与者实际使用的辅助技术。严重或意见不同的记录进入盲评队列，先填写中立的任务证据，再交给两位评审。优先复盘会列出模型放行、人工确认阻断或参与者自评困难的已定案案例。

「项目成效」显示文档到首次明确结果的中位耗时、独立盲测严重漏放数，以及已修复任务的同场景复检结果；同时查看分母与待验证数。「项目存储」分别列出应用管理的项目数据、截图和失败录制。确认清理一种媒体后，历史轮次、条款、人工记录、Agent 对话和文件备份继续保留。手动选择报告目录的 CLI 导出由该目录管理。

### 在工作流中编排测试与修复

打开项目的「工作流」，点「添加步骤」选择测试或修复、检测范围及可选名称。按列从左到右运行。拖动卡片或使用「前移」「后移」改序，也可以复制步骤、在两列之间插入复检。修复列可指定前面的某次测试作为依据，默认采用最近的匹配测试。移除或移走被引用的测试后，请在启动时重新确认顺序。页面采样支持为同一专项配置不同的预览路径。

「逐步推进」由你启动每次检测、查看结果并继续。「自动推进」可连续运行综合检查、组件映射及交互、无障碍、适配、性能页面采样。发现问题、覆盖不完整、缺少预览地址时会暂停。需要设计对比、逻辑场景、用户观察或修复时，进入对应工具操作，返回工作流选用本步取得的证据，或填写人工结果和出处。修复对话会预填依据，由你决定是否发送。把同一测试放在修复后可以重新取证。

流程与运行记录保存在项目的本地 QA大师 数据中。刷新后可继续当前列；运行中可切换模式。切为逐步时，正在执行的测试会先结束。

在「项目 → 检查」选择一个专项，展开「任务验收」，为当前轮次建立案例。先写预期、选观测，再封存模型判断，交由两人独立评审。体验专项还可记录参与者对任务难易的自评。通过「查看校准指标」核对模型漏放、人工分歧和自评困难的案例占比。 [专项工作流与指标口径](assurance-workflows.md#给每道规程建立可复查的案例)

QA大师 在本机检查前端项目，结合浏览器证据和可选 AI 复核帮助处理界面问题。一次配置范围内的检查通过，并不代表整个产品完成验收。

## 建立项目和首次检查

添加现有项目目录，查看发现的组件库和项目规范。源码检查默认只读；需要检查网页时，先启动项目自己的预览服务并配置访问地址。首次截图可能需要下载可选浏览器组件，下载前会显示说明并征求确认。

0.5.0 按「项目 → 检查 → 问题处理 → 复检」组织。UI、UX、体验问题分开查看；自动检查、AI 建议和人工观察有各自的证据边界。页面未访问、状态未触发或没有截图时，不应当作该部分通过。

## 导入检查依据

导入需求后，可在「检查 → 逻辑判断 → 从需求开始验收」保存并绑定候选任务。选择「页面操作与预期」可设置点击或填写，再核对结果文字、可见状态或操作后隐藏。运行前在「预览设置」保存测试地址。异步渲染的页面也可填写共同的就绪选择器。

可以用 `uxqa requirements --file <文档路径>` 在本机读取仓库内外的 Markdown 或纯文本。JSON 保留原文和行号，候选条款均需人工绑定。要在代码项目里保存并运行验收任务，直接把外部文档拖入该项目的检查依据。在项目预览设置里可以打开浏览器登录并确认保存。命令行新生成的报告使用 `--out` 时默认保留截图，另传 `--expire-screenshots` 才登记 48 小时清理。

只有设计稿时，可用 Figma 只读插件下载整页证据。`uxqa figma check` 核对主件状态与主题，`uxqa figma graph` 检查原型连线和明确指定的跨画板事实。键盘焦点、真实命中和保存后状态需在可访问的前端预览中验证。[Figma 采集、命令与覆盖说明](figma-readonly.md)

在项目「检查」选择检测类别，将文件拖入「拖入项目依据」，或点「选择文件」。要把一份资料用于多类检查，先进入「添加链接或仓库」，勾选类别，再拖入文件。在「本类检查依据」展开资料，点「选择原文」，核对摘录、定位和适用类别后保存。再次导入已更新的文件会生成新快照，旧条款保留原版本。

| 依据 | 操作与结果 |
| --- | --- |
| PDF、DOCX、PPTX、XLSX | 在本机提取 PDF 页、Word 段落、幻灯片段落、工作表行与单元格。扫描 PDF 的无文字页记录为缺口。旧版 DOC/XLS/PPT 请先另存为新格式。 |
| Markdown、TXT、CSV、TSV、JSON、YAML、XML、HTML | 保留可检索的原文位置。单文件最多 32 MB，提取文本最多 8 MB。 |
| PNG、JPEG、WebP、SVG | 导入单帧设计图，在资料条目点「与本轮画面比对」。核对内容、字体、主题和尺寸。缺截图或尺寸不一致时显示原因。 |
| Sketch、FIG、XD、PSD | Sketch 读取画板名称、尺寸及文字图层。FIG、XD、PSD 登记名称和文件指纹。视觉比对请附具体单帧导出图。 |
| Git 仓库、源码文件 | 粘贴 GitHub、GitLab 或其他 Git 克隆地址，可指定分支或标签。读取会连接仓库、用本机 Git 下载并静态扫描，保留提交版本及观察位置。文件入口也可读取 GitHub/GitLab 文件页或原始文本链接。私库使用本机已有 Git 凭据。 |
| Figma、Canva 与其他画板 | Figma 选具体节点，Canva 国际站选具体页；主动在线读取时，凭据仅在本次传给相应官方服务。可画中国站、其他网页画板或离线使用时，保存来源链接，在同一窗口拖入单帧导出图。仅保存链接会标为待取证。 |

**离线与模型。** QA大师 无需部署线上服务。本地解析、快照、源码扫描和同尺寸像素比较均无需模型。需解读图像或编排场景时，在「设置 → 模型」选择 Ollama、LM Studio 或兼容的局域网接口，并选择实际已装模型。要看图，模型须支持图像输入。使用云端模型时，所选摘录和项目上下文会发送到配置的端点。首次下载浏览器、模型或拉取远程资料需要能访问相应来源；已有本地快照可离线复查。

## 通用逻辑检查

在「工作流 → 验收任务」从已导入的文档生成任务。选中一条原文，展开「从这条要求创建验收场景」，选择验收类型并绑定测试页面、控件和预期。可以在本机创建并运行这些场景，无需模型。检查前先看阶段列表，准备可修改的测试数据，再点「运行任务」。

| 验收类型 | 关键证据 |
| --- | --- |
| 配置发布与生效 | 记录各读取入口、设置原值和独立对照；确认测试值有变化，发布后重开设置逐项核对。复跑前恢复初始测试数据。 |
| 确认、取消与角色结果 | 身份标识、完整行数、对象键和接收方必须可读。取消后比原清单；确认时以第二次预览为准，按对象与角色比对。 |
| 中断返回与状态保留 | 记录对象和原值，编辑后离开并返回同一对象。按所选原文检查应保留编辑还是恢复原值。 |

绑定一直指向这条原文和方案。当前置证据不足时查看具体缺口；环境或控件无法运行时查看阻塞原因。原场景复查沿用同一绑定。项目成效中的盲测误报、漏报显示人工裁定样本的分子和分母。

角色清单默认在预览关闭后读取。预览会保留时，可绑定确认或取消后新出现的完成标识。需分别登录的角色可以在 CLI 的 `actorStates` 中为 `operator` 和 `recipient:<角色标识>` 指定各自的本地测试登录状态。桌面版核对页面显示的身份，无法确认的角色会留下证据缺口。

在项目的「检查 → 检测类别」选择专项。「关联文档条款」可读取项目内 UTF-8 文本并选择原文，也可手动摘录外部文档、PDF 或设计节点。标明版本、章节或页码并勾选所有适用类别。再次打开时会核对已关联文件的摘要；修改过或已移除的文件需要重新关联。进入条款后点「用所选模型编排场景」会把该条款和当前项目检查上下文送给已配置的模型。核对场景中的角色、操作、断言与测试地址后，在项目对话中点「运行测试场景」。

「视觉还原 → 对比设计稿」支持项目内的 PNG 设计帧。选择当轮页面实测画面并核对版本与条件。结果保存在本地，可查看原始尺寸、变化像素数和差异图。「运行页面实测」可为无障碍、交互、适配或性能单独采样。「新建验证任务」用于保留人工复核的证据、状态与复检历史。各专项的输入、执行方式、限制和方法来源见[专项检测说明](assurance-workflows.md)。

没有需求文档时，可在项目修复对话中说「检查两处显示有无自相矛盾」。内置的同一事实检查会从两处分别读取对象、字段和版本标识，以及显示值。三组标识全部对得上，才比较值。字段标识应包含单位和统计口径；无法确认是否是同一快照时，结果为待验证。场景中用 `sameFact` 的 `object`、`field`、`version` 分别引用两侧的观测名。

在项目修复对话中说清期望关系，例如「操作后两处显示应一致」或「撤销后应恢复原值」。也可以指定项目文件，由助手引用其中的规则。先核对规则出处、对象、状态和观察位置，再点击「运行测试场景」。观察到两处不同，但项目没有说明应该相同时，可以记录差异，具体业务含义留待确认。

场景可把操作前后、不同页面或独立角色读取的文本、控件值或属性命名为观测值（`observe`）。断言（`assert`）能比较两个观测值，也能与规则明确指定的常量比较。文本支持相等和不等；数字用 `as: "number"` 显式读取后支持大小和边界比较。可选 `when` 表示断言适用的条件。条件未触发、值不可读或类型不可比时，该关系标为待验证；条件成立且结果相反时，标为失败。针对清单可比较稳定标识和重复次数。报告按关系给出结果和实际观测。

命令行使用相同的场景格式。在项目根目录运行 `python3 -m http.server 4189 --bind 127.0.0.1 --directory examples/logic`，然后在另一终端运行 `./uxqa run --config examples/logic/scenario.json`。桌面端每个角色从空会话开始；命令行可用 `actorStates` 指定角色的独立登录文件，路径相对于配置文件。登录文件保存在仓库外。[通用场景示例](../examples/logic/scenario.json)

## 处理与复检

完成页面实测后，记录摘要显示本次通过、偏差、阻塞和待验证的数量。内置交互场景的页面、控件绑定和前置步骤随本项目的实测记录保存在本机。展开记录，点「按原配置复测」即可在相同路径运行原场景。实测期间切到其他模块再返回，完成后会自动显示新结果。

打开「检查 → 扫描范围」，可以看到本轮每个目录实际检查了多少文件、哪些目录仅供比对，以及规则在哪些目录因何跳过。历史轮次会注明当时是否记录了这些信息。

在「检查 → 交互行为 → 运行页面实测」中选择内置场景。「失败后恢复」需要读取请求的地址匹配式、错误提示和恢复后的内容，可选择重试按钮。「保存后继续键盘操作」需要保存控件、保存后才出现的成功状态，以及预期接收焦点的控件。「切换语言后的首个入口」需要语言控件、目标语言和第一个控件的角色与译名。展开前置操作可以打开菜单或编辑测试数据。保存会在配置的测试项目上按桌面和窄屏各执行一次。未绑定场景标为待验证，准备未完成标为阻塞。

「用户体验与便利性 → 记录任务体验」用于记录实际观察。填写任务、用户群与设备条件、完成方式、遇到的困难和证据；耗时可选。QA大师 只汇总同轮、同任务、同条件的记录，将独立完成数与样本量一起展示。每个改进建议都可以追溯到对应观察，再用相同任务复测。

在「检查概览」查看当前轮次、已检查文件数和新问题数。点某个分类会直接打开该类问题并清除旧筛选。问题搜索支持中文输入法，选字完成后更新结果。在项目页签上可用左右方向键切换，Home / End 跳到首末页签。

打开问题查看位置、证据和修复方向；可以记录处理状态或人工观察。接受偏差、人工确认需要填写理由。修复后在相同规则、页面、窗口及状态下重新检测；“未再检出”本身不自动证明问题修复。

「专项修复方案」使用本轮事实、项目规范和内置知识组织待验证任务。可逐项记录结果与证据、保留历史，也可将发现的问题带入人工观察表单。记录通过是填写者提供的结论，不代表 QA大师 自动执行了该任务。详见 [质量工作流](quality-workflow.md)。

在「问题处理」中，轮次、搜索和严重程度会固定在列表上方。向下滑动会自动加载下一批问题，打开详情再返回会保留列表位置。键盘可用上下方向键浏览，Home / End 跳到首项和末项。预览页面全部打开失败时，点「检查预览地址」可直接编辑地址。

## 项目修复对话（0.5.2 及以后）

回车在草稿中换行。按 ⌘ + Enter（macOS）或 Ctrl + Enter（Windows / Linux）发送，也可以点「发送」。

项目顶部的「让 AI 修」直接打开「修复对话 → AI 修复」。在这里发送消息会调用设置中已保存的模型，回答保留在当前项目。「问题提示词复制」可预览并复制当前问题或整轮问题，超过 10 项时也可以只取前 10 项。复制在本地完成，可以随时切回对话继续写草稿。

从问题详情点「讨论并修复」，可带着当前问题进入项目对话。点「查看原问题」回到同一条证据。问题列表默认显示搜索和严重程度，展开「更多筛选」可按处理状态等条件缩小结果，点「清除筛选」可恢复完整列表。

首次进入空对话时，可以点建议问题生成草稿，编辑后再发送。从对话返回原问题会保留能显示该问题的搜索与筛选。Agent 实际修改文件后，可点「复检改动」运行新一轮检查并查看对比。复检页可以切换轮次，从「仍然检出」直接打开对应问题；「未再检出」需要结合相同页面状态验证。

在项目的「修复对话」中讨论 UI、UX 和体验问题；也可从问题详情点「讨论并修复」，两处打开同一个项目会话。先在设置中选择并保存模型。发送时会向该模型服务发送本轮最多 30 条问题摘要、对话及 Agent 实际读取的项目文件；有可用截图时默认附上当前问题截图或页面总览，可手动取消。无截图时会提示重新检查页面。

Agent 可直接读取、修改当前项目内的文本文件，也可新建文件及目录，不需要逐个授权路径。修改文件前必须先读取，新建前先查看项目；连续三次工具失败会停止。每条消息最多请求模型 24 次，同时受模型设置中的请求上限约束。它不能自由执行终端命令，不访问项目外、符号链接或常见凭据文件；组件验证可在你确认后运行项目脚本，见下文。二进制图片等不能直接按文本修改。修改前原文在本机 QA大师 数据目录备份；操作记录支持撤销，撤销创建会删除尚未被后续修改的新文件，若文件后来又被修改则需要手动处理。完成修改后 QA大师 会尝试自动复检源码，页面和截图仍需重新检查；模型的回复本身不是验收结果。该能力尚未包含在已发布的 0.5.0 下载包中。

修复时，Agent 会读取当前项目规则并发现可识别的原生组件目录。目录缺失或有歧义时不能据此断言项目没有组件；新增或抽取共享组件仍需经过项目的组件计划与同步流程。每次文件修改必须说明与当前问题或请求的关系，理由会显示在操作记录中；这不能保证模型的判断一定正确。对话顶部显示当前选中的问题，可以清除后讨论其他问题。源码复检的实际记录会反馈给模型；同一指纹没有再出现，不代表页面和交互已验证。

对话中需要新增共享组件时，Agent 可以准备绑定项目原生组件目录的计划。检查实现文件、调用位置、项目测试及类型检查脚本的实际内容和浏览器场景后，点击「运行验证并同步」；脚本和场景可能修改测试数据，请使用可信项目与测试环境。只有验证通过才会更新组件目录和规格；计划或检查配置变化时需要重新准备。截图遵循 48 小时清理策略。组件识别依赖受支持的目录格式和路径，不能自动识别所有共享组件；现有组件修订仍需明确使用项目的计划与同步流程。

- **设计候选**：要求 Agent 基于项目现状生成候选。结果可包括语义颜色、字体、间距、圆角和时长变量及候选 CSS，并计算已提供的文字与背景纯色对比度。引用项目源码时，QA大师 核对原文是否出现在本轮读取范围内并显示位置；没有引用时标记依据未核对。原文匹配不代表设计判断正确；候选不会自动成为项目规范，也不代表实际页面或无障碍状态通过。
- **方案比较**：先配置可运行的项目预览，再让 Agent 准备两个或三个方案。QA大师 在独立的临时浏览器上下文打开原版和候选，等待你比较并在对话中选择；可以临时调整多个现有元素的受支持样式、叶节点文字和位置，不改源码。框架重新渲染可能撤销预览，不能预览任意结构或原生组件。非 GET/HEAD 请求和 WebSocket 被拦截，部分交互可能不可用；GET 端点也可能有副作用，请使用测试环境。可在对话中关闭预览，退出 QA大师 也会关闭。
- **代码方案比较**：需要比较会随页面重新渲染的结构或行为时，Agent 可读取同源预览页面、脚本或样式资源并准备方案；读取的片段会发送给所选模型。常见凭据路径和疑似密钥会被拦截，模式检查不能保证发现所有敏感内容。展开每个方案核对原文和替换内容，再点「运行代码方案并比较」；只有本轮实际读取、原文唯一且加载时摘要未变化的脚本或样式可替换。代码会在不导入已保存登录状态的独立浏览器中运行；常规跨域、重定向、写请求和 WebSocket 被阻止，但 GET 仍可能改变数据，浏览器不是安全沙箱，请仅使用可信测试环境。只支持加载页面时请求的资源，依赖登录、外部资源、重定向或延迟加载的页面可能无法预览。初始错误与失败请求单独记录，后续交互需自行检查；选定方案后仍需让 Agent 修改真实项目源码并复检。
- **动效采样**：要求 Agent 测量悬停、焦点、静态、滚动或点击场景，按需模拟减少动态效果。修改前后比较要求页面、元素、浏览器、窗口、触发方式、动效偏好和实际滚动距离一致。点击需在该条消息中启用页面点击；请使用测试环境，GET 端点仍可能有副作用。记录包括帧回调间隔、长任务、目标与整页动画，以及可用的 Chromium 主线程计数；计数可能重叠并包含采样开销。未观察到实际滚动不会标记为完成；这不是 GPU 掉帧、真机性能或全部手势的结论。

## 权限和联网

0.5.0 的首次引导说明访问范围并允许检查选定项目目录；设置中显示该目录最近一次实际读取的结果。结果不等于永久系统授权。QA大师 在启动时重新检查此前可访问的位置，开始项目检查时也会检查项目目录；这不是对系统权限的实时监控，调整系统设置后可在 QA大师 中点“重新检查”。macOS 通常保存用户选择，但目录移动、磁盘断开、系统设置变更或应用更新后仍可能无法访问。拒绝访问时请检查系统“隐私与安全性 → 文件与文件夹”，再重新检查；也可移除 QA大师 的访问记录而不删除目录。

QA大师 的项目列表、检查结果、模型配置和项目对话保存在 `~/.uxqa`（Windows 为 `%USERPROFILE%\.uxqa`，可由 `UXQA_HOME` 覆盖）。普通检查不会更改项目源码；保存项目规范、基线、组件同步，以及 Agent 修复会写入项目。可选预览、浏览器下载、AI 复核和修复对话可能联网。详见 [本地数据与权限](local-data-and-permissions.md)。

## 模型和账号

在设置中配置 API 协议或支持的订阅账号，获取模型，选择支持图片的模型，测试并保存。连接成功不等于每个模型、账号或套餐均可用。Claude 订阅需要官方 Claude Code；Google 订阅需要自行配置获准的 OAuth 客户端。账号凭据保存在本机，不能宣称一定使用系统钥匙串加密。

安装、系统提示、更新和卸载见 [安装与使用](install-and-use.md)。请核对下载版本；较早版本可能不包含上述功能。
