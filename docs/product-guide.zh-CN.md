# UXQA 使用说明

UXQA 在本机检查前端项目，结合浏览器证据和可选 AI 复核帮助处理界面问题。一次配置范围内的检查通过，并不代表整个产品完成验收。

## 建立项目和首次检查

添加现有项目目录，查看发现的组件库和项目规范。源码检查默认只读；需要检查网页时，先启动项目自己的预览服务并配置访问地址。首次截图可能需要下载可选浏览器组件，下载前会显示说明并征求确认。

0.5.0 按「项目 → 检查 → 问题处理 → 复检」组织。UI、UX、体验问题分开查看；自动检查、AI 建议和人工观察有各自的证据边界。页面未访问、状态未触发或没有截图时，不应当作该部分通过。

## 处理与复检

打开问题查看位置、证据和修复方向；可以记录处理状态或人工观察。接受偏差、人工确认需要填写理由。修复后在相同规则、页面、窗口及状态下重新检测；“未再检出”本身不自动证明问题修复。

「专项修复方案」使用本轮事实、项目规范和内置知识组织待验证任务。可逐项记录结果与证据、保留历史，也可将发现的问题带入人工观察表单。记录通过是填写者提供的结论，不代表 UXQA 自动执行了该任务。详见 [质量工作流](quality-workflow.md)。

## 项目修复对话（0.5.2 开发版，尚未发布）

在项目的「修复对话」中讨论 UI、UX 和体验问题；也可从问题详情点「讨论并修复」，两处打开同一个项目会话。先在设置中选择并保存模型。发送时会向该模型服务发送本轮最多 30 条问题摘要、对话及 Agent 实际读取的项目文件；有可用截图时默认附上当前问题截图或页面总览，可手动取消。无截图时会提示重新检查页面。

Agent 可直接读取、修改当前项目内的文本文件，也可新建文件及目录，不需要逐个授权路径。修改文件前必须先读取，新建前先查看项目；连续三次工具失败会停止。每条消息最多请求模型 24 次，同时受模型设置中的请求上限约束。它不能自由执行终端命令，不访问项目外、符号链接或常见凭据文件；组件验证可在你确认后运行项目脚本，见下文。二进制图片等不能直接按文本修改。修改前原文在本机 UXQA 数据目录备份；操作记录支持撤销，撤销创建会删除尚未被后续修改的新文件，若文件后来又被修改则需要手动处理。完成修改后 UXQA 会尝试自动复检源码，页面和截图仍需重新检查；模型的回复本身不是验收结果。该能力尚未包含在已发布的 0.5.0 下载包中。

修复时，Agent 会读取当前项目规则并发现可识别的原生组件目录。目录缺失或有歧义时不能据此断言项目没有组件；新增或抽取共享组件仍需经过项目的组件计划与同步流程。每次文件修改必须说明与当前问题或请求的关系，理由会显示在操作记录中；这不能保证模型的判断一定正确。对话顶部显示当前选中的问题，可以清除后讨论其他问题。源码复检的实际记录会反馈给模型；同一指纹没有再出现，不代表页面和交互已验证。

对话中需要新增共享组件时，Agent 可以准备绑定项目原生组件目录的计划。检查实现文件、调用位置、项目测试及类型检查脚本的实际内容和浏览器场景后，点击「运行验证并同步」；脚本和场景可能修改测试数据，请使用可信项目与测试环境。只有验证通过才会更新组件目录和规格；计划或检查配置变化时需要重新准备。截图遵循 48 小时清理策略。组件识别依赖受支持的目录格式和路径，不能自动识别所有共享组件；现有组件修订仍需明确使用项目的计划与同步流程。

- **设计候选**：要求 Agent 基于项目现状生成候选。结果可包括语义颜色、字体、间距、圆角和时长变量及候选 CSS，并计算已提供的文字与背景纯色对比度。引用项目源码时，UXQA 核对原文是否出现在本轮读取范围内并显示位置；没有引用时标记依据未核对。原文匹配不代表设计判断正确；候选不会自动成为项目规范，也不代表实际页面或无障碍状态通过。
- **方案比较**：先配置可运行的项目预览，再让 Agent 准备两个或三个方案。UXQA 在独立的临时浏览器上下文打开原版和候选，等待你比较并在对话中选择；可以临时调整多个现有元素的受支持样式、叶节点文字和位置，不改源码。框架重新渲染可能撤销预览，不能预览任意结构或原生组件。非 GET/HEAD 请求和 WebSocket 被拦截，部分交互可能不可用；GET 端点也可能有副作用，请使用测试环境。可在对话中关闭预览，退出 UXQA 也会关闭。
- **代码方案比较**：需要比较会随页面重新渲染的结构或行为时，Agent 可读取同源预览页面、脚本或样式资源并准备方案；读取的片段会发送给所选模型。常见凭据路径和疑似密钥会被拦截，模式检查不能保证发现所有敏感内容。展开每个方案核对原文和替换内容，再点「运行代码方案并比较」；只有本轮实际读取、原文唯一且加载时摘要未变化的脚本或样式可替换。代码会在不导入已保存登录状态的独立浏览器中运行；常规跨域、重定向、写请求和 WebSocket 被阻止，但 GET 仍可能改变数据，浏览器不是安全沙箱，请仅使用可信测试环境。只支持加载页面时请求的资源，依赖登录、外部资源、重定向或延迟加载的页面可能无法预览。初始错误与失败请求单独记录，后续交互需自行检查；选定方案后仍需让 Agent 修改真实项目源码并复检。
- **动效采样**：要求 Agent 测量悬停、焦点、静态、滚动或点击场景，按需模拟减少动态效果。修改前后比较要求页面、元素、浏览器、窗口、触发方式、动效偏好和实际滚动距离一致。点击需在该条消息中启用页面点击；请使用测试环境，GET 端点仍可能有副作用。记录包括帧回调间隔、长任务、目标与整页动画，以及可用的 Chromium 主线程计数；计数可能重叠并包含采样开销。未观察到实际滚动不会标记为完成；这不是 GPU 掉帧、真机性能或全部手势的结论。

## 权限和联网

0.5.0 的首次引导说明访问范围并允许检查选定项目目录；设置中显示该目录最近一次实际读取的结果。结果不等于永久系统授权。UXQA 在启动时重新检查此前可访问的位置，开始项目检查时也会检查项目目录；这不是对系统权限的实时监控，调整系统设置后可在 UXQA 中点“重新检查”。macOS 通常保存用户选择，但目录移动、磁盘断开、系统设置变更或应用更新后仍可能无法访问。拒绝访问时请检查系统“隐私与安全性 → 文件与文件夹”，再重新检查；也可移除 UXQA 的访问记录而不删除目录。

UXQA 的项目列表、检查结果、模型配置和项目对话保存在 `~/.uxqa`（Windows 为 `%USERPROFILE%\.uxqa`，可由 `UXQA_HOME` 覆盖）。普通检查不会更改项目源码；保存项目规范、基线、组件同步，以及 Agent 修复会写入项目。可选预览、浏览器下载、AI 复核和修复对话可能联网。详见 [本地数据与权限](local-data-and-permissions.md)。

## 模型和账号

在设置中配置 API 协议或支持的订阅账号，获取模型，选择支持图片的模型，测试并保存。连接成功不等于每个模型、账号或套餐均可用。Claude 订阅需要官方 Claude Code；Google 订阅需要自行配置获准的 OAuth 客户端。账号凭据保存在本机，不能宣称一定使用系统钥匙串加密。

安装、系统提示、更新和卸载见 [安装与使用](install-and-use.md)。请核对下载版本；较早版本可能不包含上述功能。
