# UXQA 使用说明

UXQA 在本机检查前端项目，结合浏览器证据和可选 AI 复核帮助处理界面问题。一次配置范围内的检查通过，并不代表整个产品完成验收。

## 建立项目和首次检查

添加现有项目目录，查看发现的组件库和项目规范。源码检查默认只读；需要检查网页时，先启动项目自己的预览服务并配置访问地址。首次截图可能需要下载可选浏览器组件，下载前会显示说明并征求确认。

0.5.0 按「项目 → 检查 → 问题处理 → 复检」组织。UI、UX、体验问题分开查看；自动检查、AI 建议和人工观察有各自的证据边界。页面未访问、状态未触发或没有截图时，不应当作该部分通过。

## 处理与复检

打开问题查看位置、证据和修复方向；可以记录处理状态或人工观察。接受偏差、人工确认需要填写理由。修复后在相同规则、页面、窗口及状态下重新检测；“未再检出”本身不自动证明问题修复。

「专项修复方案」使用本轮事实、项目规范和内置知识组织待验证任务。可逐项记录结果与证据、保留历史，也可将发现的问题带入人工观察表单。记录通过是填写者提供的结论，不代表 UXQA 自动执行了该任务。详见 [质量工作流](quality-workflow.md)。

## 权限和联网

0.5.0 的首次引导说明访问范围并允许检查选定项目目录；设置中显示该目录最近一次实际读取的结果。结果不等于永久系统授权。UXQA 在启动时重新检查此前可访问的位置，开始项目检查时也会检查项目目录；这不是对系统权限的实时监控，调整系统设置后可在 UXQA 中点“重新检查”。macOS 通常保存用户选择，但目录移动、磁盘断开、系统设置变更或应用更新后仍可能无法访问。拒绝访问时请检查系统“隐私与安全性 → 文件与文件夹”，再重新检查；也可移除 UXQA 的访问记录而不删除目录。

UXQA 的项目列表、检查结果和模型配置保存在 `~/.uxqa`（Windows 为 `%USERPROFILE%\.uxqa`，可由 `UXQA_HOME` 覆盖）。普通检查不会更改项目源码；保存项目规范、基线和组件同步属于明确的项目写入动作。可选预览、浏览器下载和 AI 复核可能联网，AI 复核会发送选定的截图及上下文。详见 [本地数据与权限](local-data-and-permissions.md)。

## 模型和账号

在设置中配置 API 协议或支持的订阅账号，获取模型，选择支持图片的模型，测试并保存。连接成功不等于每个模型、账号或套餐均可用。Claude 订阅需要官方 Claude Code；Google 订阅需要自行配置获准的 OAuth 客户端。账号凭据保存在本机，不能宣称一定使用系统钥匙串加密。

安装、系统提示、更新和卸载见 [安装与使用](install-and-use.md)。请核对下载版本；较早版本可能不包含上述功能。
